This page shows you how to upsert documents into a collection.

The examples write to the default branch, `main`. The REST request accepts an optional `branch` field. To write to another branch, [create it first](/guides/data-versioning/branches-tags-aliases#create-and-list-branches), then include its name in `branch`; a tag or alias is not a valid write target.

Document field names are preserved as supplied in every SDK. The examples use `dense_vector` and `sparse_vector`; configure indexes with those same names to search these values. The dense examples use synthetic 64-dimensional vectors; configure `dense_vector` with `dimensions: 64`. For real data, send the full vectors from your embedding model, matching the field's dimensions (64–4096).

<Note>

  If the collection contains native embedding vector fields, send only the configured source text fields. Do not send direct vector values for native embedding fields in an upsert request.

</Note>

  import { LambdaDBClient } from "@functional-systems/lambdadb";

  const client = new LambdaDBClient({
    projectApiKey: "YOUR_API_KEY",
    baseUrl: "YOUR_BASE_URL",
    projectName: "YOUR_PROJECT_NAME",

  const collection = client.collection("my_collection");
  await collection.docs.upsert({

  ```go Go
  package main

  import (
    "context"
    "log"
    lambdadb "github.com/lambdadb/go-lambdadb"
  )

  func main() {
    ctx := context.Background()
    client := lambdadb.New(
      lambdadb.WithBaseURL("YOUR_BASE_URL"),
      lambdadb.WithProjectName("YOUR_PROJECT_NAME"),
      lambdadb.WithAPIKey("YOUR_API_KEY"),
    )
    coll := client.Collection("my_collection")
    demoVector := func(offset int) []float64 {
      values := make([]float64, 64)
      for i := range values { values[i] = float64(i + offset) / 64 }
      return values
    }
    myDocs := []map[string]interface{}{
      {"id": "33201222", "url": "https://en.wikipedia.org/wiki/LambdaDB", "title": "LambdaDB", "text": "LambdaDB is the vector lake for AI memory ... ", "dense_vector": demoVector(1), "sparse_vector": map[string]float64{"LambdaDB": 0.83, "is": 0.1, "a": 0.1, "AI": 0.7}},
      {"id": "33201223", "url": "https://en.wikipedia.org/wiki/Winamp", "title": "Winamp", "text": "Winamp is a media player for Windows, macOS and Android ...", "dense_vector": demoVector(11)},
    }
    _, err := coll.Docs().Upsert(ctx, lambdadb.UpsertDocsInput{Docs: myDocs})
    if err != nil {
      log.Fatal(err)
    }
  }
  ```

## Response

```json
{
  "message": "Upsert request is accepted"
}
```

Each document implicitly contains an `id` field in order to uniquely identify a document.
A unique string value is auto-generated by the system if `id` field is not provided in an upsert request.
If you want to overwrite the entire document, you can do so by providing the `id` field in the document.

## IDs and retries

The acceptance response does not return auto-generated IDs. If you need to fetch, update, delete, or retry a document later, assign its ID before sending the request. Repeating an upsert without an ID can create another document with a new ID.

Keep the same ID, branch, and partition-field value when replaying a write. An upsert replaces the entire document at that identity, so replaying an older payload can overwrite newer changes. Stable IDs prevent duplicate identities; they do not make writes conditional on the current document version.

If a request times out or the connection closes after dispatch, its outcome may be unknown. [Fetch the expected IDs](/guides/documents/fetch-data) from the same branch with `consistentRead: true` and, for a partitioned collection, a `partitionFilter` selecting the original partition. Compare the stored content with the intended payload before deciding whether a retry is still needed. Do not infer write failure from an empty eventually consistent result. If that verification also fails, retain the unknown outcome and use the [error-specific retry guidance](/reference/api/introduction#errors-and-retries).

<Info>

  For a partitioned collection, documents are upserted into the `__default__` partition if the partition field is not provided.

</Info>

## Upsert limits

| Metric                       | Limit           |
| :--------------------------- | :-------------- |
| Max payload size             | 6MB             |
| Max length for a document ID | 512 characters  |
| Max vector dimensions        | 4,096           |
| Max document size            | 5MB            |

When upserting larger amounts of data, it is recommended to use
[bulk-upsert](/guides/documents/bulk-upsert-data) operation.
