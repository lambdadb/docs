This page shows you how to use the delete endpoint to remove documents from a collection.

The examples delete from the default branch, `main`. To delete from another existing writable branch, pass its name in the optional `branch`, in the REST body or on the SDK call (`branch` in Python and TypeScript, `Branch` in Go), as in [Upsert into a branch](/guides/documents/upsert-data#upsert-into-a-branch). A tag or alias is not a valid write target. See [Branch selection](/guides/data-versioning/branches-tags-aliases#write-to-a-branch).

Specify exactly one of `ids` or `filter`. An empty request, both fields together, or `partitionFilter` alone returns `400 BadRequest`. For partitioned collections, `partitionFilter` narrows the IDs or filter selection; it is not an independent deletion selector.

## Delete documents by IDs

Since LambdaDB documents can always be efficiently accessed using their ID,
deleting by ID is the most efficient way to remove specific records.

<CodeGroup>
  
  ```python Python
  from lambdadb import LambdaDB

  with LambdaDB(
      project_api_key="YOUR_API_KEY",
      base_url="YOUR_BASE_URL",
      project_name="YOUR_PROJECT_NAME",
  ) as client:
      coll = client.collection("your_collection_name")
      coll.docs.delete(ids=["example-doc-id-1", "example-doc-id-2"])
  ```

  ```typescript TypeScript
  import { LambdaDBClient } from "@functional-systems/lambdadb";

  const client = new LambdaDBClient({
    projectApiKey: "YOUR_API_KEY",
    baseUrl: "YOUR_BASE_URL",
    projectName: "YOUR_PROJECT_NAME",
  });
  await client.collection("your_collection_name").docs.delete({
    ids: ["example-doc-id-1", "example-doc-id-2"],
  });
  ```

  ```go Go
  package main

  import (
    "context"
    "log"
    lambdadb "github.com/lambdadb/go-lambdadb"
  )

  func main() {
    ctx := context.Background()
    client := lambdadb.New(
      lambdadb.WithBaseURL("YOUR_BASE_URL"),
      lambdadb.WithProjectName("YOUR_PROJECT_NAME"),
      lambdadb.WithAPIKey("YOUR_API_KEY"),
    )
    _, err := client.Collection("your_collection_name").Docs().Delete(ctx, lambdadb.DeleteDocsInput{
      Ids: []string{"example-doc-id-1", "example-doc-id-2"},
    })
    if err != nil {
      log.Fatal(err)
    }
  }
  ```

  ```bash cURL
  BASE_URL="YOUR_BASE_URL"
  PROJECT_NAME="YOUR_PROJECT_NAME"
  COLLECTION_NAME="your_collection_name"
  LAMBDADB_PROJECT_API_KEY="YOUR_API_KEY"

  curl -i -X POST \
    --url "$BASE_URL/projects/$PROJECT_NAME/collections/$COLLECTION_NAME/docs/delete" \
    --header 'content-type: application/json' \
    --header "x-api-key: $LAMBDADB_PROJECT_API_KEY" \
    --data '{
    "ids": [
      "example-doc-id-1",
      "example-doc-id-2"
    ]
  }'
  ```
  
</CodeGroup>

## Delete documents by query

To delete documents based on their data, pass a `filter` query to the delete operation.
This deletes all documents matching the filter query.

For example, to delete all documents with genre "documentary" and year 2019 from a collection, use the following code:

These snippets reuse the imports, client setup, and cURL variables above. For Go, replace the ID-deletion call inside `main` with the filter example below.

<CodeGroup>
  
  ```python Python
  with LambdaDB(
      project_api_key="YOUR_API_KEY",
      base_url="YOUR_BASE_URL",
      project_name="YOUR_PROJECT_NAME",
  ) as client:
      coll = client.collection("your_collection_name")
      coll.docs.delete(query_filter={"queryString": {"query": "genre:documentary AND year:2019"}})
  ```

  ```typescript TypeScript
  await client.collection("your_collection_name").docs.delete({
    filter: { queryString: { query: "genre:documentary AND year:2019" } },
  });
  ```

  ```go Go
  filter := map[string]any{
    "queryString": map[string]any{"query": "genre:documentary AND year:2019"},
  }
  _, err := client.Collection("your_collection_name").Docs().Delete(ctx, lambdadb.DeleteDocsInput{Filter: filter})
  if err != nil {
    log.Fatal(err)
  }
  ```

  ```bash cURL
  curl -i -X POST \
    --url "$BASE_URL/projects/$PROJECT_NAME/collections/$COLLECTION_NAME/docs/delete" \
    --header 'content-type: application/json' \
    --header "x-api-key: $LAMBDADB_PROJECT_API_KEY" \
    --data '{
    "filter": {
      "queryString": {
        "query": "genre:documentary AND year:2019"
      }
    }
  }'
  ```

</CodeGroup>

## Delete all documents from a branch

This example clears all partitions on the existing `candidate` branch. Before deleting, inspect the same branch with a query that returns up to one document ID.

```bash
curl -i -X POST \
  "$BASE_URL/projects/$PROJECT_NAME/collections/$COLLECTION_NAME/query" \
  -H "Content-Type: application/json" \
  -H "x-api-key: $LAMBDADB_PROJECT_API_KEY" \
  -d '{
    "ref": { "kind": "branch", "name": "candidate" },
    "size": 1,
    "fields": { "include": ["id"] }
  }'
```

Use the match-all query `*:*` as the deletion filter. To clear the default branch instead, set both the query's `ref.name` and the delete request's `branch` to `main`.

```bash
curl -i -X POST \
  "$BASE_URL/projects/$PROJECT_NAME/collections/$COLLECTION_NAME/docs/delete" \
  -H "Content-Type: application/json" \
  -H "x-api-key: $LAMBDADB_PROJECT_API_KEY" \
  -d '{
    "branch": "candidate",
    "filter": { "queryString": { "query": "*:*" } }
  }'
```

A `202 Accepted` response confirms the deletion was submitted. Default reads reflect the deletion after a snapshot containing it is published. Run the same query again after publication and check for `"total": 0`.

This operation preserves the collection, the branch schema, other branches, and tags. Aliases that target the branch reflect its updated data. Tags and retained snapshots may still contain the deleted documents.
