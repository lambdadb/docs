This page shows you how to use the list endpoint to list documents in a collection. Use this when you need to iterate over documents (for example, to export or scan) without running a ranked search.

Large responses may return documents through `docsUrl` instead of inline `docs`. See [Large results](/guides/search/limits#large-results) for REST download instructions and SDK behavior.

| Parameter   | Description                                      | Type    | Required | Default |
| :---------- | :----------------------------------------------- | :------ | :------- | :------ |
| size        | Max number of documents to return per page; see [page limits](/guides/get-started/limits#search-and-reads). | integer |          | 100     |
| pageToken   | Token for the next page of results.              | string  |          |         |
| includeVectors | Indicates whether vector values are included in the response. | boolean |          | false   |
| refKind     | Ref type: `branch`, `tag`, or `alias`; use with `refName`. | string | | |
| refName     | Ref name; use with `refKind`. | string | | |

Treat `pageToken` as opaque and return it unchanged to the same endpoint. When selecting a ref, supply `refKind` and `refName` together; omitting both reads from `main`. See [Read from a ref](/guides/data-versioning/branches-tags-aliases#read-from-a-ref) for examples.

Documents are returned in ascending document ID order unless an [extended list request](#extended-list-request) sorts them. A list request on a branch reads its published snapshot. On a tag, or an alias that targets a tag, it also includes the pending writes the tag captured. To include a branch's pending writes, set `consistentRead` in an extended list request. Pending bulk imports become visible after they are published. A read that includes pending writes can return `429` when that pending payload reaches the [configured threshold](/guides/get-started/limits#search-and-reads).

Page tokens record a position in the requested order, not a snapshot. Each page reads the data currently visible to the ref, so documents added after the position can appear on later pages and documents disappear once their deletion is visible to the read. Between pages, a branch may advance, an alias may be retargeted, and a tag may publish pending writes it captured at creation. For a stable multi-page export, use the same [tag created with `source.asOf`](/guides/data-versioning/branches-tags-aliases#create-and-list-tags) on every page. Keep the page size and the sort, filter, partition, field-selection, vector, and consistency options unchanged: a changed request condition returns `400 BadRequest`, as does reusing a token with a different project, collection, or ref. Start again from the first page when any of them changes.

<CodeGroup>

  ```python Python
  from lambdadb import LambdaDB

  with LambdaDB(
      project_api_key="YOUR_API_KEY",
      base_url="YOUR_BASE_URL",
      project_name="YOUR_PROJECT_NAME",
  ) as client:
      coll = client.collection("my_collection")
      # List first page of documents
      res = coll.docs.list(size=10)
      # `res.results` contains items (each item includes `doc` and metadata).
      # `res.documents` contains document bodies only.
      for item in res.results:
          print(item)

      # List next page using the token from the previous response
      if res.next_page_token:
          res_next = coll.docs.list(size=10, page_token=res.next_page_token)
  ```

  ```typescript TypeScript
  import { LambdaDBClient } from "@functional-systems/lambdadb";

  const client = new LambdaDBClient({
    projectApiKey: "YOUR_API_KEY",
    baseUrl: "YOUR_BASE_URL",
    projectName: "YOUR_PROJECT_NAME",
  });
  const collection = client.collection("my_collection");

  // List first page
  const options = { size: 20 };
  const res = await collection.docs.list(options);
  console.log(res.docs?.length, res.total);

  // List next page
  if (res.nextPageToken) {
    const resNext = await collection.docs.list({
      ...options,
      pageToken: res.nextPageToken,
    });
  }
  ```

  ```go Go
  package main

  import (
    "context"
    "log"
    lambdadb "github.com/lambdadb/go-lambdadb"
  )

  func main() {
    ctx := context.Background()
    client := lambdadb.New(
      lambdadb.WithBaseURL("YOUR_BASE_URL"),
      lambdadb.WithProjectName("YOUR_PROJECT_NAME"),
      lambdadb.WithAPIKey("YOUR_API_KEY"),
    )
    coll := client.Collection("my_collection")

    // List first page
    res, err := coll.Docs().List(ctx, &lambdadb.ListDocsOpts{Size: lambdadb.Int64(10)})
    if err != nil {
      log.Fatal(err)
    }
    for _, d := range res.Docs {
      _ = d
    }

    // List next page
    if res.NextPageToken != nil {
      resNext, _ := coll.Docs().List(ctx, &lambdadb.ListDocsOpts{
        Size:      lambdadb.Int64(10),
        PageToken: res.NextPageToken,
      })
      _ = resNext
    }
  }
  ```

  ```bash cURL
  # List first page ($BASE_URL and $PROJECT_NAME match SDK base_url / project_name)
  curl -X GET "$BASE_URL/projects/$PROJECT_NAME/collections/$COLLECTION_NAME/docs?size=10" \
    -H "x-api-key: $LAMBDADB_PROJECT_API_KEY"

  # Include vector values when needed
  curl -X GET "$BASE_URL/projects/$PROJECT_NAME/collections/$COLLECTION_NAME/docs?size=10&includeVectors=true" \
    -H "x-api-key: $LAMBDADB_PROJECT_API_KEY"

  # List next page (use nextPageToken from previous response)
  curl -X GET "$BASE_URL/projects/$PROJECT_NAME/collections/$COLLECTION_NAME/docs?size=10&pageToken=YOUR_PAGE_TOKEN" \
    -H "x-api-key: $LAMBDADB_PROJECT_API_KEY"
  ```

</CodeGroup>

    },
    {
      "collection": "example-collection-name",

        "category": "docs"
      }
    }

  "nextPageToken": "ZXlKcFpDSTZJQ0poWW1NaQ",

## Extended list request

For filtering, partition filtering, sorting, field selection, pending writes, or a JSON request body, use the extended list endpoint:

<CodeGroup>

  ```python Python
  from lambdadb import LambdaDB

  with LambdaDB(
      project_api_key="YOUR_API_KEY",
      base_url="YOUR_BASE_URL",
      project_name="YOUR_PROJECT_NAME",
  ) as client:
      coll = client.collection("my_collection")

      res = coll.docs.list(
          size=10,
          filter_={"queryString": {"query": "category:docs"}},
          partition_filter={"field": "tenant", "in": ["acme"]},
          fields={"include": ["id", "title", "category"]},
          include_vectors=False,
      )
  ```

  ```typescript TypeScript
  import { LambdaDBClient } from "@functional-systems/lambdadb";

  const client = new LambdaDBClient({
    projectApiKey: "YOUR_API_KEY",
    baseUrl: "YOUR_BASE_URL",
    projectName: "YOUR_PROJECT_NAME",
  });

  const res = await client.collection("my_collection").docs.list({
    size: 10,
    filter: { queryString: { query: "category:docs" } },
    partitionFilter: { field: "tenant", in: ["acme"] },
    fields: { include: ["id", "title", "category"] },
    includeVectors: false,
  });
  ```

  ```go Go
  package main

  import (
    "context"
    "log"

    lambdadb "github.com/lambdadb/go-lambdadb"
    "github.com/lambdadb/go-lambdadb/models/components"
  )

  func main() {
    ctx := context.Background()
    client := lambdadb.New(
      lambdadb.WithBaseURL("YOUR_BASE_URL"),
      lambdadb.WithProjectName("YOUR_PROJECT_NAME"),
      lambdadb.WithAPIKey("YOUR_API_KEY"),
    )

    fields := components.CreateFieldsSelectorUnionFieldsSelector1(components.FieldsSelector1{
      Include: []string{"id", "title", "category"},
    })

    res, err := client.Collection("my_collection").Docs().List(ctx, &lambdadb.ListDocsOpts{
      Size: lambdadb.Int64(10),
      Filter: map[string]any{
        "queryString": map[string]any{"query": "category:docs"},
      },
      PartitionFilter: &components.PartitionFilter{
        Field: "tenant",
        In:    []string{"acme"},
      },
      Fields:         &fields,
      IncludeVectors: lambdadb.Bool(false),
    })
    if err != nil {
      log.Fatal(err)
    }
    _ = res
  }
  ```

  ```bash cURL
  curl -X POST "$BASE_URL/projects/$PROJECT_NAME/collections/$COLLECTION_NAME/docs/list" \
    -H "Content-Type: application/json" \
    -H "x-api-key: $LAMBDADB_PROJECT_API_KEY" \
    --data '{
      "size": 10,
      "filter": {
        "queryString": {
          "query": "category:docs"
        }
      },
      "partitionFilter": {
        "field": "tenant",
        "in": ["acme"]
      },
      "fields": {
        "include": ["id", "title", "category"]
      },
      "includeVectors": false
    }'
  ```

</CodeGroup>

The scoped list helpers (`docs.list` in Python and TypeScript, `Docs().List` in Go) use the extended POST endpoint when you pass a filter, partition filter, field selector, sort order, or enable consistent reads.

In TypeScript 0.15.0, `consistentRead: false` also selects POST. Python 0.17.0 treats `consistent_read=False` like omission when choosing the endpoint. In Go 0.11.0, setting `Ref` or `ConsistentRead` on `lambdadb.ListDocsOpts` selects POST, including when you pass `lambdadb.Bool(false)` for `ConsistentRead`. Use `Filter`, `PartitionFilter`, `Fields`, `Sort`, and `IncludeVectors` for the corresponding Go options.

Page tokens are tied to the request method and options. Reuse the first request's options and change only the page token, as in the [sorted list examples](#sort-and-read-pending-writes).

The extended list request body supports:

| Parameter      | Description                                                  | Type    | Required | Default |
| :------------- | :----------------------------------------------------------- | :------ | :------- | :------ |
| size           | Max number of documents to return per page; see [page limits](/guides/get-started/limits#search-and-reads).         | integer |          | 100     |
| pageToken      | Token for the next page of results.                          | string  |          |         |
| filter         | Filter applied before pagination. Supports `queryString` and nested `bool` filters. | object  |          |         |
| partitionFilter | Restricts the request to matching partition values.         | object  |          |         |
| sort           | Order by up to four `keyword`, `long`, `double`, or `datetime` fields, as objects of one field and `asc` or `desc`. See [Sort and read pending writes](#sort-and-read-pending-writes). | object[] |          | Ascending document ID |
| consistentRead | Include the pending writes of a branch, or of an alias that targets a branch. A tag or an alias that targets a tag rejects `true`. | boolean |          | false   |
| fields         | Field selector with `include` and/or `exclude`. Use dot notation for nested fields. | object  |          |         |
| includeVectors | Indicates whether vector values are included in the response. | boolean |          | false   |
| ref            | Branch, tag, or alias selector as `{ "kind": "...", "name": "..." }`. | object | | `main` branch |

`filter` uses the same `queryString` and `bool` shapes as the query API. List filters do not run vector or ranking queries.
Use `partitionFilter` only for collections configured with a partition field.
Inside a `bool` filter, `occur` can be `filter`, `must`, `must_not`, or `should`; when omitted, it defaults to `should`.

```json
{
  "filter": {
    "bool": [
      {
        "queryString": {
          "query": "category:docs"
        },
        "occur": "filter"
      },
      {
        "queryString": {
          "query": "title:LambdaDB"
        },
        "occur": "must"
      }
    ]
  }
}
```

### Sort and read pending writes

These requests return pages ordered by `category`, including writes to `main` that are not yet in its published snapshot. The SDK examples read a second page with the same arguments:

<CodeGroup>

  ```python Python
  from lambdadb import LambdaDB

  with LambdaDB(
      project_api_key="YOUR_API_KEY",
      base_url="YOUR_BASE_URL",
      project_name="YOUR_PROJECT_NAME",
  ) as client:
      coll = client.collection("my_collection")

      res = coll.docs.list(size=10, sort=[{"category": "asc"}], consistent_read=True)
      if res.next_page_token:
          res_next = coll.docs.list(
              size=10,
              sort=[{"category": "asc"}],
              consistent_read=True,
              page_token=res.next_page_token,
          )
  ```

  ```typescript TypeScript
  import { LambdaDBClient, type ListDocsInput } from "@functional-systems/lambdadb";

  const client = new LambdaDBClient({
    projectApiKey: "YOUR_API_KEY",
    baseUrl: "YOUR_BASE_URL",
    projectName: "YOUR_PROJECT_NAME",
  });
  const collection = client.collection("my_collection");

  const request: ListDocsInput = {
    size: 10,
    sort: [{ category: "asc" }],
    consistentRead: true,
  };
  const res = await collection.docs.list(request);
  if (res.nextPageToken) {
    const resNext = await collection.docs.list({ ...request, pageToken: res.nextPageToken });
  }
  ```

  ```go Go
  package main

  import (
    "context"
    "log"

    lambdadb "github.com/lambdadb/go-lambdadb"
  )

  func main() {
    ctx := context.Background()
    client := lambdadb.New(
      lambdadb.WithBaseURL("YOUR_BASE_URL"),
      lambdadb.WithProjectName("YOUR_PROJECT_NAME"),
      lambdadb.WithAPIKey("YOUR_API_KEY"),
    )
    coll := client.Collection("my_collection")

    opts := &lambdadb.ListDocsOpts{
      Size:           lambdadb.Int64(10),
      Sort:           []map[string]any{{"category": "asc"}},
      ConsistentRead: lambdadb.Bool(true),
    }
    res, err := coll.Docs().List(ctx, opts)
    if err != nil {
      log.Fatal(err)
    }

    // Next page: the same options with the returned token
    if res.NextPageToken != nil {
      opts.PageToken = res.NextPageToken
      resNext, err := coll.Docs().List(ctx, opts)
      if err != nil {
        log.Fatal(err)
      }
      _ = resNext
    }
  }
  ```

  ```bash cURL
  curl -X POST "$BASE_URL/projects/$PROJECT_NAME/collections/$COLLECTION_NAME/docs/list" \
    -H "Content-Type: application/json" \
    -H "x-api-key: $LAMBDADB_PROJECT_API_KEY" \
    --data '{
      "size": 10,
      "sort": [{"category": "asc"}],
      "consistentRead": true
    }'
  ```

</CodeGroup>

In the SDKs, the paging helpers (`list_pages` in Python, `listPages` or `listAll` in TypeScript, and `ListIterator` or `ListAll` in Go) repeat these options and the page size on every page. In Python and TypeScript, a `sort` direction other than `asc` or `desc` fails before a request is sent, and so does `consistentRead: true` (`consistent_read=True` in Python) with a tag ref; Go sends the request and returns the server's `400`.

Fields are compared in the order given, and ascending document ID breaks ties. Omit `sort` or send `null` for the default order; an empty array returns `400 BadRequest`. For a `keyword` array, `asc` uses the smallest indexed value and `desc` the largest. A document without a `keyword` value sorts last for `asc` and first for `desc`; a missing numeric or `datetime` value sorts as zero (the Unix epoch for `datetime`). If a document's sort value changes between pages, that document can be returned again or skipped.

<Note>

  When you use `nextPageToken` with the extended endpoint, repeat the original request body with the token as `pageToken`: keep the same `size`, `sort`, `consistentRead`, `filter`, `partitionFilter`, `fields`, `includeVectors`, and `ref` options across pages.

</Note>

<Note>

  To fetch specific documents by ID, use the [fetch](/guides/documents/fetch-data) endpoint. To run ranked text, vector, sparse-vector, or hybrid search, use the [query](/guides/search/search-overview) API.

</Note>
