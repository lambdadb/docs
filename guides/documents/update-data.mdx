This page shows you how to update documents in a collection.

The examples write to the default branch, `main`. The REST request accepts an optional `branch` field. To write to another branch, [create it first](/guides/data-versioning/branches-tags-aliases#create-and-list-branches), then include its name in `branch`; a tag or alias is not a valid write target.

<Note>

  If the collection contains native embedding vector fields, update the configured source text fields instead of sending direct vector values for native embedding fields. Unchanged source text reuses an existing vector; see [Native embedding write behavior](/guides/collections/native-embeddings#write-behavior).

</Note>

  ```go Go
  package main

  import (
    "context"
    "log"
    lambdadb "github.com/lambdadb/go-lambdadb"
  )

  func main() {
    ctx := context.Background()
    client := lambdadb.New(
      lambdadb.WithBaseURL("YOUR_BASE_URL"),
      lambdadb.WithProjectName("YOUR_PROJECT_NAME"),
      lambdadb.WithAPIKey("YOUR_API_KEY"),
    )
    docs := []map[string]interface{}{
      {"id": "33201222", "title": "LambdaDB", "text": "LambdaDB is the vector lake for AI memory ... "},
      {"id": "33201223", "title": "Winamp v2", "text": "Winamp v2 is a media player for Windows, macOS and Android."},
    }
    _, err := client.Collection("my_collection").Docs().Update(ctx, lambdadb.UpdateDocsInput{Docs: docs})
    if err != nil {
      log.Fatal(err)
    }
  }
  ```

<Info>
  
  Each document in a payload must contain an `id` field to uniquely identify a document to update.
  For a partitioned collection, a document in the `__default__` partition with a matching `id` value is updated if the partition field is not provided.

</Info>

## How fields are updated

An update reads the existing document with strong consistency, merges the supplied fields into it, and submits the resulting document for indexing. Omitted fields remain unchanged. The resulting document must still satisfy the collection's field types and document-size limit.

| Supplied value | Behavior |
|:---------------|:---------|
| Scalar | Replaces the existing value |
| Object | Recursively merges into an existing object, preserving omitted nested fields |
| Array | Replaces the entire array; elements are not appended or merged |
| `null` | Rejected with HTTP `400` for an indexed field. On an unindexed field, stores JSON `null`; it does not remove the field |

For example, assume `metadata` is an object field and `labels` is a keyword field. Start with this document:

```json
{
  "id": "doc-1",
  "title": "Refund policy",
  "metadata": { "language": "en", "revision": 1 },
  "labels": ["draft", "support"]
}
```

Send this update request:

```json
{
  "docs": [
    {
      "id": "doc-1",
      "metadata": { "revision": 2 },
      "labels": ["published"]
    }
  ]
}
```

After the update becomes visible, the document is:

```json
{
  "id": "doc-1",
  "title": "Refund policy",
  "metadata": { "language": "en", "revision": 2 },
  "labels": ["published"]
}
```

An empty object does not clear an existing object. To remove fields, use [upsert](/guides/documents/upsert-data) with the complete replacement document and omit those fields.

## Missing documents and failed requests

Update does not create documents. If any ID is missing from the selected branch and partition, the request returns HTTP `400` and none of its updates are submitted. Use upsert when a document may not exist. Updating a partitioned document requires its existing partition-field value; omitting that field selects `__default__` and does not move a document from another partition.

Input validation and native embedding generation complete before the merged documents are submitted. A failure in either stage prevents submission of the whole update request. A `202 Accepted` response confirms acceptance, not completed indexing. A timeout or transport failure after submission can still leave the write applied; [verify the resulting state before retrying](/reference/api/introduction#errors-and-retries).

## Concurrent updates and cost

Update is a read-modify-write operation without a document-version precondition. Concurrent requests can read the same earlier document and submit different replacements, overwriting each other's changes even when they update different fields. Serialize writes to the same document when preserving concurrent changes matters.

The internal strongly consistent fetch is billed as read usage in addition to the update's write usage. See [Write usage](/guides/costs/understanding-costs#write-usage).

## Update limits

| Metric                       | Limit           |
| :--------------------------- | :-------------- |
| Max payload size             | 6MB             |
| Max length for a document ID | 512 characters  |
| Max vector dimensions        | 4,096           |
| Max document size            | 5MB            |
