This page shows you how to manage your existing collections including listing, describing, configuring, and deleting operations.

Later snippets reuse the imports and client setup from the first example. For Go, place the snippets inside `main`, import `context`, `log`, and `github.com/lambdadb/go-lambdadb` as `lambdadb`, and initialize `ctx := context.Background()`. See the [Start with an SDK](/guides/get-started/quickstart) for a complete Go setup.

The examples use the `example-collection` schema from [Create a collection from scratch](/guides/collections/create-a-collection#create-a-collection-from-scratch).

## List collections

Retrieve collections in your project with their configuration and metadata. The endpoint supports optional pagination.

| Parameter  | Description                                      | Type    | Required | Default |
| :--------- | :----------------------------------------------- | :------ | :------- | :------ |
| size       | Max number of collections to return in one page, from 1 to 100. | integer |          | 10      |
| pageToken  | Token for the next page of results.              | string  |          |         |

Treat `pageToken` as opaque. Return it unchanged to the same endpoint, and omit it for the first page: an empty or malformed `pageToken`, a `size` outside the range, or any other query parameter returns `400 BadRequest`.

<CodeGroup>

```python Python
from lambdadb import LambdaDB

with LambdaDB(project_api_key="YOUR_API_KEY", base_url="YOUR_BASE_URL", project_name="YOUR_PROJECT_NAME") as client:
    # First page (optional: size, page_token)
    res = client.collections.list(size=20)
    for c in res.collections:
        print(c.collection_name, c.num_docs)
    # Next page (if res.next_page_token is set)
    if res.next_page_token:
        res_next = client.collections.list(size=20, page_token=res.next_page_token)
```

```typescript TypeScript
import { LambdaDBClient } from "@functional-systems/lambdadb";

```

## Describe a collection

Get detailed information about a specific collection, including its configuration, document count, default branch, and retention period. `indexConfigs`, `numDocs`, and `dataUpdatedAt` describe the default `main` branch: its index schema and its committed head. Other branches carry their own schema and statistics; read them from the [branch routes](/guides/data-versioning/branches-tags-aliases#list-and-describe-branches). They are not totals across branches or statistics for a selected ref. `dataUpdatedAt` may be absent before the first snapshot commits.

<CodeGroup>

```python Python
with LambdaDB(project_api_key="YOUR_API_KEY", base_url="YOUR_BASE_URL", project_name="YOUR_PROJECT_NAME") as client:
    meta = client.collections.get(collection_name="example-collection")
    print(meta.collection)
```

```typescript TypeScript
const meta = await client.collection("example-collection").get();
console.log(meta);
```

```go Go
meta, err := client.Collection("example-collection").Get(ctx)
if err != nil { log.Fatal(err) }
log.Printf("%+v", meta)
```

```bash cURL
curl -i -X GET "$BASE_URL/projects/$PROJECT_NAME/collections/example-collection" \
  -H "x-api-key: $LAMBDADB_PROJECT_API_KEY"
```

</CodeGroup>

The REST response wraps the collection details in `collection`. SDK convenience methods may return the inner object:

```json

  "collection": {
    "projectName": "your-project",
    "collectionName": "example-collection",
    "indexConfigs": {
      "url": { "type": "keyword" },
      "author": { "type": "keyword" },
      "content": {
        "type": "text",
        "analyzers": ["japanese", "korean", "english"],
        "description": "Article body in Japanese, Korean, or English"
      },
      "id": { "type": "keyword" }
    },
    "description": "Articles searchable by URL, author, and content",
    "tags": {"environment": "production"},
    "numDocs": 1250,
    "numPartitions": 1,

```

Collection and ref timestamps, including `source.asOf`, use numeric Unix epoch milliseconds. A field's `description` appears in `indexConfigs` only when one is set; see [Field descriptions](/guides/collections/index-types#field-descriptions).

## Configure a collection

Update one or more of `description`, `tags`, or `snapshotRetentionInDays`:

<CodeGroup>

```python Python
with LambdaDB(project_api_key="YOUR_API_KEY", base_url="YOUR_BASE_URL", project_name="YOUR_PROJECT_NAME") as client:
    client.collections.update(
        collection_name="example-collection",
        description="Validated article catalog",
        tags={"environment": "production"},
        snapshot_retention_in_days=14,
    )
```

```typescript TypeScript
await client.collection("example-collection").update({
  description: "Validated article catalog",
  tags: { environment: "production" },
  snapshotRetentionInDays: 14,
});
```

```go Go
_, err = client.Collection("example-collection").Update(ctx, lambdadb.UpdateCollectionOptions{
  Description:             lambdadb.String("Validated article catalog"),
  Tags:                    map[string]string{"environment": "production"},
  SnapshotRetentionInDays: lambdadb.Int64(14),
})
if err != nil { log.Fatal(err) }
```

```bash cURL
curl -i -X PATCH \
  "$BASE_URL/projects/$PROJECT_NAME/collections/example-collection" \
  -H "content-type: application/json" \
  -H "x-api-key: $LAMBDADB_PROJECT_API_KEY" \
  -d '{
    "description": "Validated article catalog",
    "tags": { "environment": "production" },
    "snapshotRetentionInDays": 14
  }'
```

</CodeGroup>

The REST response is `200 OK` with the full `collection` wrapper. Omitted or `null` fields remain unchanged; at least one supported field must be non-null.

| Field | Supplied value |
| :---- | :------------- |
| `description` | Replaces the description; `""` clears it. See [metadata limits](/guides/get-started/limits#collections-and-schema). |
| `tags` | Replaces the entire metadata map, rather than merging keys; `{}` clears it. |
| `snapshotRetentionInDays` | Integer within the [supported retention range](/guides/get-started/limits#collections-and-schema); there is no unlimited-retention value for this setting. Snapshots pinned by an existing tag remain available beyond this period; see [Snapshot retention](/guides/collections/create-a-collection#snapshot-retention). |
| `indexConfigs` | Deprecated on this route. It updates the schema of the default `main` branch only, exactly as the branch route does; see [Update the index schema](#update-the-index-schema). |

`partitionConfig` and `defaultBranchName` cannot be changed with PATCH.

### Update the index schema

Collection responses show the `indexConfigs` of the default `main` branch. To change a schema, update the branch that owns it.

This update adds a `category` index and retains the existing `url`, `author`, and `content` settings. It omits the server-managed `id` and the existing `content` description, which LambdaDB preserves. The Go snippet also imports `github.com/lambdadb/go-lambdadb/models/components`.

<CodeGroup>

```python Python
with LambdaDB(project_api_key="YOUR_API_KEY", base_url="YOUR_BASE_URL", project_name="YOUR_PROJECT_NAME") as client:
    client.collection("example-collection").branches.update(
        "main",
        index_configs={
            "url": {"type": "keyword"},
            "author": {"type": "keyword"},
            "content": {"type": "text", "analyzers": ["japanese", "korean", "english"]},
            "category": {"type": "keyword"},
        },
    )
```

```typescript TypeScript
await client.collection("example-collection").branches.update("main", {
  indexConfigs: {
    url: { type: "keyword" },
    author: { type: "keyword" },
    content: { type: "text", analyzers: ["japanese", "korean", "english"] },
    category: { type: "keyword" },
  },
});
```

```go Go
_, err = client.Collection("example-collection").Branches().Update(ctx, "main", lambdadb.UpdateBranchInput{
  IndexConfigs: map[string]components.IndexConfigsUnion{
    "url": components.CreateIndexConfigsUnionKeyword(components.IndexConfigs{Type: components.TypeKeyword}),
    "author": components.CreateIndexConfigsUnionKeyword(components.IndexConfigs{Type: components.TypeKeyword}),
    "content": components.CreateIndexConfigsUnionText(components.IndexConfigsText{
      Type:      components.TypeTextText,
      Analyzers: []components.Analyzer{components.AnalyzerJapanese, components.AnalyzerKorean, components.AnalyzerEnglish},
    }),
    "category": components.CreateIndexConfigsUnionKeyword(components.IndexConfigs{Type: components.TypeKeyword}),
  },
})
if err != nil { log.Fatal(err) }
```

```bash cURL
curl -i -X PATCH \
  "$BASE_URL/projects/$PROJECT_NAME/collections/example-collection/branches/main" \
  -H "content-type: application/json" \
  -H "x-api-key: $LAMBDADB_PROJECT_API_KEY" \
  -d '{
    "indexConfigs": {
      "url": { "type": "keyword" },
      "author": { "type": "keyword" },
      "content": { "type": "text", "analyzers": ["japanese", "korean", "english"] },
      "category": { "type": "keyword" }
    }
  }'
```

</CodeGroup>

The response is `200 OK` with the updated `branch`, including its `indexConfigs`. Updating `main` also changes the `indexConfigs` shown on the collection. Updating any other branch leaves `main` and the collection unchanged; see [Branch index schemas](/guides/data-versioning/branches-tags-aliases#branch-index-schemas).

Sending `indexConfigs` to `PATCH .../collections/{collectionName}` still works and updates `main` the same way, but that path is deprecated. The SDK, CLI, and MCP server versions listed under [supported SDK versions](/reference/sdk/introduction#supported-sdk-versions) provide the branch update shown above and mark `indexConfigs` on their collection update as deprecated; in the CLI, use [`branches update`](/guides/get-started/use-with-cli#update-a-branch-index-schema) instead of `collections update --index-config`.

Submit a nonempty full schema that preserves existing fields and their settings while adding top-level or nested fields. A field's `description` is the only existing setting that can change. New fields can be added under existing objects at any depth. Include all existing fields in the submitted schema, including nested children, and preserve their types and settings. For example, adding `profile.city` is supported when `profile.name` and its settings are retained. Removing an existing field or changing its type, analyzers, vector settings, or embedding configuration is rejected.

### Field descriptions

Every field in `indexConfigs`, including nested `objectIndexConfigs` children, accepts an optional `description` of up to 255 characters. It is metadata only: it never affects indexing, and changing it does not reindex the field. On create, omitting it, `null`, or `""` means no description. On PATCH, omitting a field's `description` or sending `null` keeps the stored value, `""` clears it, and any other string replaces it. The server-managed `id` field does not accept a description. See [Field descriptions](/guides/collections/index-types#field-descriptions) for examples on every index type.

To change only the `content` description after adding `category`, resend the full schema with the new description and every other setting unchanged.

```bash
curl -i -X PATCH \
  "$BASE_URL/projects/$PROJECT_NAME/collections/example-collection/branches/main" \
  -H "content-type: application/json" \
  -H "x-api-key: $LAMBDADB_PROJECT_API_KEY" \
  -d '{
    "indexConfigs": {
      "url": { "type": "keyword" },
      "author": { "type": "keyword" },
      "content": {
        "type": "text",
        "analyzers": ["japanese", "korean", "english"],
        "description": "Full article text used for search"
      },
      "category": { "type": "keyword" }
    }
  }'
```

The response returns the updated `branch`, and the `content` field keeps its analyzers and indexed data.

Described and listed collections include the server-managed top-level `id` field as `{"type": "keyword"}`. You can send a described `indexConfigs` back unchanged, with that `id` entry, or omit it; any other `id` configuration, an `id` inside an object field, or another reserved field name is rejected.

Metadata tags must follow the [entry count, key, and value rules](/guides/get-started/limits#collections-and-schema). These metadata tags are separate from data-versioning tags.

## Delete a collection

Permanently delete a collection and all of its associated data and resources. This operation cannot be undone.

The API performs the logical deletion transition before returning `200 OK`. The deleted collection becomes unavailable and its name can be reused immediately.

Physical cleanup may continue after the response. Recreating the name creates a new collection identity; discard cached state for the old collection. Deleting an already absent collection can return `404`.

<CodeGroup>

```python Python
with LambdaDB(project_api_key="YOUR_API_KEY", base_url="YOUR_BASE_URL", project_name="YOUR_PROJECT_NAME") as client:
    client.collections.delete(collection_name="collection-to-delete")
```

```typescript TypeScript
await client.collection("collection-to-delete").delete();
```

```go Go
_, err = client.Collection("collection-to-delete").Delete(ctx)
if err != nil { log.Fatal(err) }
```

```bash cURL
curl -i -X DELETE "$BASE_URL/projects/$PROJECT_NAME/collections/collection-to-delete" \
  -H "x-api-key: $LAMBDADB_PROJECT_API_KEY"
```

</CodeGroup>

The REST response is:

```json
{
  "message": "Collection deletion requested"
}
```

<Warning>
Deleting a collection is irreversible and will permanently remove all documents and metadata. Make sure you have proper backups if needed before proceeding with this operation.
</Warning>
