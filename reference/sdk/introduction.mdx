## Supported SDK versions

The examples use these stable releases, which include data versioning, all 49 [text analyzer presets](/guides/collections/choose-text-analyzers), [native reranking](/guides/search/native-reranking), [Bayesian hybrid search](/guides/search/hybrid#bayesian-hybrid-query), and [native embedding configuration](/guides/collections/native-embeddings#collection-schema):

| SDK | Recommended release | SDK guide |
| :-- | :------------------ | :-------- |
| Python | [0.12.1](https://pypi.org/project/lambdadb/0.12.1/) | [Python data versioning](https://github.com/lambdadb/lambdadb-python-client/blob/v0.12.1/docs/sdks/versioning/README.md) |
| JavaScript/TypeScript | [0.8.1](https://www.npmjs.com/package/@functional-systems/lambdadb/v/0.8.1) | [TypeScript data versioning](https://github.com/lambdadb/lambdadb-typescript-client/blob/v0.8.1/docs/data-versioning.md) |
| Go | [0.7.1](https://github.com/lambdadb/go-lambdadb/releases/tag/v0.7.1) | [Go data versioning](https://github.com/lambdadb/go-lambdadb/blob/v0.7.1/docs/sdks/versioning/README.md) |

Python SDK 0.12.1 requires Python **3.10–3.13**. If you use Python 3.9, stay on `lambdadb==0.9.0` until upgrading Python; that release does not include the additional analyzer names. Go SDK 0.7.1 requires Go **1.22 or later**.

### Search and embedding configuration

For Bayesian queries, select the candidate budget field based on whether reranking is enabled:

| Client or request format | Without reranking | With reranking |
|:-------------------------|:------------------|:---------------|
| REST JSON / Python wire dictionary | Top-level `candidateSize` | `rerank.candidateSize` |
| Python SDK model | Query argument `candidate_size` | Rerank model field `candidate_size` |
| TypeScript SDK | Top-level `candidateSize` | `rerank.candidateSize` |
| Go SDK | `QueryInput.CandidateSize` | `RerankConfig.CandidateSize` |

Without reranking, the budget is required and must satisfy `1 <= size <= candidateSize <= 100`. With reranking, omit the top-level field; the rerank budget defaults to `max(50, size)` and must satisfy the same bounds. `knn.k` remains independent. See the [complete Bayesian requests](/guides/search/hybrid#bayesian-hybrid-query) for both forms. Existing search defaults are unchanged.

Native embedding configuration accepts `embedding` without `managedEmbedding`; legacy `managedEmbedding: true` remains supported for older servers.

TypeScript and Go provide `IndexConfigsNativeEmbeddingVector`; Go wraps this with `CreateIndexConfigsUnionNativeEmbeddingVector`. Existing legacy SDK types and helpers remain available.

## Data versioning support

The minimum stable versions for collection, branch, tag, and alias APIs remain Python **0.9.0**, JavaScript/TypeScript **0.5.1**, and Go **0.4.0**. Use the recommended releases above for all 49 fixed analyzer presets and native reranking. Older SDK request and response models may reject or omit the new fields.

Start with the [SDK examples](/guides/data-versioning/branches-tags-aliases#use-the-sdks) to create a branch, write to it, and read from a selected ref. The language-specific guides cover tags, aliases, pagination, and bulk uploads. Python also provides async methods; JavaScript/TypeScript uses promises and async iterators, while Go uses `context.Context`.

For analyzer support through the SDKs, CLI, and MCP server, see [analyzer SDK compatibility](/guides/collections/choose-text-analyzers#sdk-compatibility).

REST timestamps use Unix epoch milliseconds. Python exposes numeric timestamps with datetime helpers such as `created_at_dt`; the TypeScript collection-scoped client returns `Date` values; Go provides time getters. Branch parent and snapshot fields can be null, so check them before accessing their fields.
